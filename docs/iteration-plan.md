# 工作驾驶舱：迭代记录与后续计划

本记录依据本轮讨论整理。第一批以同步可靠性和现有任务规则一致性为范围；后续方案属于待实施或待验证设计，不等于已上线功能。

## 第一批实施范围（PR #30，已合并）

以下记录第一批行为；涉及长期跟进和本周关系的规则，以第二批为准。

- 云同步：上传期间的新修改串行补传；只有最新内容收到确认才显示“已同步”。失败保留本机内容，后续编辑、立即同步或网络恢复可重试。
- 冲突：检测到冲突后暂停自动及强制上传，保留现有“采用云端 / 保留本机”的显式处理入口和恢复快照。
- 账号：已退出或切换会话的迟到上传响应不能更新当前账号的同步状态。
- 拖动：同一卡片排序不执行类型、状态、日期转换；跨卡片转换复用共享规则。跟进日期仅在主动离开“等待”状态时按现有规则清除，移入长期跟进、普通排序不再无条件清除。
- 今日安排：可执行的活跃事项计划日期到达后，实际写入今日标记，并维持“今日同时加入本周”的既有字段关系。长期跟进类型保留，仍按既有规则排除在本周行动清单之外。
- 自动激活例外：等待、暂停、已完成、已归档、待处理/收件箱事项不自动进入执行区。收件箱与待处理的绑定尚未调整。
- 改期：详情中改到未来日期后移出今日，保留本周安排和跟进日期；到新日期再激活。直接加入今日仍可覆盖未来计划的当前执行选择。
- 手动取消今日：取消已到期的计划日期，避免立即重新进入；未来计划日期与跟进日期保留。该行为在入口提示中说明，可通过撤销恢复。本轮没有新增“本次已处理”记录或日期消费字段。
- 入口一致性：加入今日、跨卡片进入今日使用同一状态转换；详情状态修改复用状态处理，包含原有重复事项生成逻辑。结束状态不得保留亮起的今日标记。
- 启动、跨日、恢复前台时检查日期；仅处理当前事项，不按今天重新激活历史周快照里的事项。
- 类型选项、状态名称、页面布局、已有任务/项目/附件/恢复快照/历史周的数据结构不做迁移。

## 验证范围

使用隔离样例和模拟云端响应，不读写真实业务数据。新增测试覆盖上传中编辑、重复调度、失败重试、离线恢复、冲突暂停、迟到响应、日期激活/改期、同区拖动和不同入口的一致性。既有静态与 Chromium 回归继续作为提交检查。

模拟云端验证不能替代实际服务与网络环境的使用观察；云端权限、服务可用性和真实双设备验收不在本轮完成范围。

## 第二批：项目总览、本周闭环、今日行动与布局

用户已同意按建议实施原未修改项 1—4。

- 项目页默认进入连续分组总览；可切换原项目详情。活跃项目即使没有事项仍显示标题，支持单项目折叠、全部展开和收起，以及未完成、暂停、完成、全部筛选。未完成默认排除暂停；已归档项目有独立入口。
- 每行显示事项、状态与备注记录、下一步及安排。备注展示可展开的原文摘录，不推断最新结论、不新增必填进展字段。下一步直接编辑原事项；等待事项安排跟进日期，其他事项安排计划日期。
- 长期跟进允许直接加入本周且保留类型。加入本周不复制事项；仅改变类型也不清除日期或本周安排。周页面的长期跟进区显示尚未安排本周的长期事项；拖入该区明确表示取消本周安排，同时处理已到期的计划日期，避免立即自动加回；未来日期和跟进日期保留。
- 本周行动清单改名“本周推进事项”。首次加入当周时带入下一步作为当周推进内容；在周页面可直接修改，之后当前下一步的变化不回写它。同周移出后再次加入保留已有当周文字和结果。
- 安排与复盘共用同一周的 Top 3 和事项记录。复盘增加 Top 3 实际结果、逐项原安排与实际进展对照，完成事项仍可对照原安排；保留原周总结富文本编辑器。
- 周记录新增可选 `actions`（按事项 ID 保存 `text` / `result`）和 `topResults`。沿用原存储版本与同步渠道，旧记录可读取；历史周没有保存过的推进内容显示未记录，不用当前下一步补写。
- 跨周关闭保留既有任务、项目及动作快照；新周继续事项使用新周开始时的下一步，实际结果重新留空。Top 3 排序或删除时，其对应结果随之一起处理。
- 今日行动主文字为下一步，缺省回退事项名称；辅助显示事项和项目。今日先做复用原置顶与排序，到期事项不会越过置顶事项。按项目分组时仍沿用原规则，暂隐藏置顶入口而不删除置顶记录。
- 今天页为左侧行动及速记、右侧等待、底部整行收件箱。任务列表随主页面滚动，取消任务区定高和速记/收件箱左右分隔；保留行动/等待分宽及速记输入框调高。
- 等待区默认展开到期、逾期事项；未到期和无日期事项以明确数量入口收起，未到期显示最近跟进日期。展开状态在本次会话中的页面重绘后保留，各日期分组内使用原排序。
- 增加字段附近短提示与问号说明，问号支持鼠标悬停、键盘聚焦、点击和 Escape 关闭。完成框始终表示整个事项完成，未加入“本次已处理”机制。

## 第三批：任务条布局、详情入口与自动保存

- 今日、本周、等待、项目详情和历史周任务条统一为“左侧拖动/完成、中间正文、右侧状态操作”的结构；在真正窄的任务卡片中，右侧操作区整体换到正文下方，避免按钮插入标题。
- 今日行动固定按“下一步动作 → 事项名称 → 项目”纵向阅读；本周推进内容单独占据正文区域。周复盘把事项状态放在实际进展框左侧，整行垂直居中；窄屏改为上下排列。
- 项目总览改为项目上下文、里程碑和统计优先的分组卡片；备注明确显示为备注记录，事项下一步与排期仍直接修改原事项，避免退化为第二个所有事项表。
- 事项标题成为统一详情入口，覆盖今日、本周、所有事项、项目总览、项目详情和里程碑关联事项；原铅笔按钮不再作为主要入口。历史周标题进入对应的只读周快照。
- 任务详情输入采用 700ms 防抖自动保存，并显示等待保存、已保存或校验失败状态。点击弹窗外部、关闭按钮或按 Escape 时先保存，再关闭；事项名称为空且已有其他内容时保持弹窗打开，避免静默丢失。完全空白的新建弹窗可直接关闭且不创建空事项。
- 检查项新增、删除、勾选、文字修改和拖动排序均进入相同自动保存链路。自动保存沿用本地持久化和现有云同步调度，不新增第二套数据源。

## 第四批：真实数据视觉收口

- 根据真实页面截图重新分配项目总览任务行：任务信息、下一步、排期按稳定比例排列，排期列限制最大宽度，避免中部空洞和下一步被压窄。
- 项目备注摘要限制为一行，无备注时不再占据一整块提示区域；下一步输入默认使用无边框阅读态，悬停或聚焦时才呈现编辑边界。
- 本周推进任务把任务身份、推进内容和状态操作放进同一布局上下文；宽卡片保持三列，较窄卡片将状态区对齐到推进内容下方，避免挤入标题。
- 所有事项把今日与本周合并为一个“行动”列，保留两个独立标记；备注仅在存在内容时显示一行摘要。表格取消独立纵向滚动，统一使用主页面滚动。
- 浏览器回归增加项目列宽、任务行高度、本周状态对齐、行动列数量和主页面滚动检查；覆盖宽屏与窄屏真实内容组合。
- 修复项目总览和本周推进文本框未继承全宽规则的问题：编辑框铺满所在规划列，并随长内容自动增高，避免右侧空间闲置和内部滚动。

## 代码结构整理（本轮）

- 按任务规则、周规则、存储、云同步、各页面、详情与富文本拆分源码，增加确定性构建与生成文件一致性检查；保留现有静态部署方式。
- 任务命令和详情自动保存复用同一个规范化、当周捕获、保存与渲染流程。
- 将当前任务行、规划输入、事项表格、复盘、项目总览与响应式规则分文件维护，清理 40 处旧选择器或被覆盖的声明。
- 同步比较和本地保存直接序列化，撤销和上传仍使用独立副本。批量规划文本框统一测量高度，窗口 resize 按帧合并。
- 本轮没有新增“本次已处理”、分类改动或存储迁移。后续按 `docs/code-structure.md` 的职责位置修改。

## 云同步初始化失败修复

- 用户截图显示云端初始读取 401 后，立即同步发起 INSERT，返回 23505 / 409 主键冲突。复现证实旧代码把“读取失败后未确认”错误当成了“云端无记录”。此前可靠性测试默认已完成初始化，未覆盖此路径。
- 增加 remoteReady 状态；自动保存和手动同步在云端状态未知时，先读取并对照版本，不直接新增。并发初始化及重试合并为一次检查。
- 认证失败的读取最多刷新会话一次，再次失败则停止；写入认证失败后也重新进入待核对状态。刷新、失败和迟到响应均校验当前账号与会话代次。
- 两端首次创建碰撞的 23505 会重新读取云端并进入冲突选择，保留本机和云端内容，不盲目 upsert。
- 新增 9 项启动/认证/重试测试，覆盖截图路径、网络恢复、不同版本冲突、并发点击及迟到响应。旧实现不能通过这些场景，修复后通过。

## 暂缓方案：本次已处理

先维持“完成框 = 整个事项完成”。仅突出下一步，使用现有备注/周记录表达阶段进展。

如真实使用仍证明必要，再设计“本次已处理”：是否退出今日、如何保留当次文字与时间、重新激活条件、无下一步时的提示、如何撤销、如何进入周复盘。不得默认增加今日/本周/整体三套强制完成操作。

## 仍需探讨的业务边界

1. 已确定并在第二批实施：长期跟进可以直接加入本周推进事项，保留长期跟进类型。
2. 到期自动激活目前不接收收件箱事项；解绑状态后，“尚未整理但有计划日期”如何处理。
3. 取消今日目前取消已到期计划日期；若未来需要保留每次原始安排，应结合行动历史一起设计，而不是悄悄重加今日。
4. 进入等待时保留原计划日期，离开等待可能因原日期已到重新进入今日；未来是否需要让界面同时询问新的行动安排。
5. 详情里的“当前进展”和“下一步”要避免同一内容重复填写；优先复用已有字段，再评估是否增加简短进展字段。
6. 恢复版本继续保留；不因“个人使用”或“云同步已开启”删除恢复能力。历史周与恢复备份用途不同。
7. WIP（Work in Progress，在制工作）只作为主动推进数量的轻量提示，不限制任务总量；等待事项单独呈现，到期催办保留明显入口。

## 产品边界

个人工作台；事项单一数据源；相关事项仅用于跳转和上下文。暂不增加父子任务、复杂前置依赖、关键路径或多人协作系统。每批独立验证再合并，后续优先解决项目浏览与排期困难。
