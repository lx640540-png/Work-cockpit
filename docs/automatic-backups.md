# 自动备份：部署与恢复

本功能分为数据库保护、Worker 后台和页面入口。代码合入不代表已经启用 Google Drive 自动备份；必须完成下列配置，并看到一份“已校验”版本。

## 部署顺序

1. 在测试项目运行 `supabase/migrations/202611110001_backups.sql`，执行 `tests/backup/sql-assertions.sql`。CI 用独立 PostgreSQL 和合成数据重复测试；不使用真实任务作为测试夹具。
2. 在 Google Cloud 项目启用 Google Drive API，配置 OAuth 同意屏幕，建立 **Web application** OAuth 客户端。授权重定向 URI 必须精确设为 `https://work-cockpit.lx640540.workers.dev/api/backups/oauth/callback`。只申请 `drive.file` 范围，备份放在由此应用创建的“工作台自动备份”文件夹。
3. 在 Cloudflare 的 `work-cockpit` Worker 中设置以下 **Secrets**，不要写入仓库、网页或 Local Storage：

| Secret | 用途 |
| --- | --- |
| `SUPABASE_SERVICE_ROLE_KEY` | 后台读取指定账号状态和附件；只能在服务端使用 |
| `GOOGLE_CLIENT_ID` | Google OAuth 客户端标识 |
| `GOOGLE_CLIENT_SECRET` | Google OAuth 客户端密钥 |
| `BACKUP_ENCRYPTION_KEY` | 随机 32 字节的 Base64 值，用于 AES-256-GCM 加密刷新令牌 |

`BACKUP_ENCRYPTION_KEY` 可在自己的终端用 `openssl rand -base64 32` 生成。保存到密码管理器；更换或丢失后必须重新连接 Google。加密数据绑定用户 ID，不能被另一个账号解密。

4. 检查 `wrangler.jsonc` 的 `SUPABASE_URL`、`BACKUP_ORIGIN`、`BACKUP_ALLOWED_USER_ID` 与部署目标匹配。这三个公开配置不是密码。预览/测试环境必须使用自己的 Supabase 测试项目、测试账号和 Google 客户端，禁止把正式后台密钥配置进界面试用站点。
5. 在正式环境执行已经验证的数据库迁移，并部署同一版本的 Worker + 静态页面。迁移为新增表、函数、权限和触发器，不替换现有 `app_states` 数据。部署前保留人工 JSON 导出。
6. 登录工作台，在“数据与恢复”刷新状态，点击“连接 Google Drive”完成一次授权，然后“立即备份”。只有下载回读、解压、状态和附件校验都通过才显示“已校验”。最后做一次隔离恢复演练再把此功能视为可用保护。

Google OAuth 必须具备适合长期使用的发布状态；处于测试状态的外部应用不应视为长期授权。权限撤销、令牌过期或配额不足都会显示失败，重新连接后可重试。OAuth 凭据不会通过 ChatGPT 的 Google Drive 连接自动提供。

## 触发与保留

- Cron 为 UTC 每小时第 17 分钟；电脑关机仍运行，但只保护已同步的云端状态。本机未上传内容必须先同步或人工导出。
- 内容变化才生成新的 Drive 版本；忽略自动更新时间和内嵌快照变化，避免空转备份。手工触发也不会无意义重复上传同一内容。
- 最近 48 小时保留小时版本；近 30 天每天保留一个版本；始终保留最近一份已校验正常版本。时间分组使用 UTC。
- 先完成新备份校验，再清理超期备份（移入 Drive 回收站）；二进制附件采用内容哈希去重，第一版不自动删除附件，以免破坏仍保留的版本。
- 数据库在正常写入前按小时保留独立旧版本；确认替换前逐次保存旧版本。独立历史的普通版本按小时/每日保留，确认替换和手工检查点保留 90 天；只有已有 Drive 校验成功记录时才执行历史清理。
- 当前状态为空、某类内容归零、或原有至少 10 条的分类骤降超过一半，会进入隔离，不覆盖正常基线。隔离版本不当作成功备份，也不在首版提供直接解除隔离按钮。
- 失败时按退避时间重试；每次 Cron 优先捕获并保护最新云端内容，再处理一个到期重试版本。并发任务使用账号互斥和带租约的更新；同一版本与哈希唯一，预分配的 Drive 文件 ID 用于上传重试。

## 覆盖范围和限制

- Drive 归档保留完整原始状态，包括任务、项目、排序、周历史、工作记录、速记、内嵌快照。数据库独立历史移除内嵌快照的副本，避免历史递归增长。
- 读取指定账号在 `task-attachments` 和 `task-files` 两个存储桶下的全部对象，包含富文本图片。归档中的附件引用必须能在备份清单中找到；原文件缺失会停止整份备份。
- 首版单附件上限为 **20 MiB**，解压后的归档上限 **25 MiB**。超过时显示失败，不能标为完整成功。限制用于控制 Worker 内存；扩大限制前应改为流式/分片处理。
- 任务数量和文件数量较大时需核对 Cloudflare 的 CPU、子请求数、执行时长及 Google Drive 的存储/API 配额；不能以“请求已排队”代替成功状态。
- 当前数据库保护会拦截最后一条某类数据的删除，以及批量清空。页面会暂停上传，用户核对后通过“替换云端”明确确认；旧页面遇到该保护应刷新到新页面。

## 恢复

1. 在历史版本中点击“预览并恢复”，先核对任务、项目、备忘和记录数量。
2. 当前本机内容先保存到独立键（最多 3 份，不在主状态里）。保存失败会停止恢复；此副本仍可能受浏览器清理影响。
3. Drive 恢复会验证归档 SHA-256、每个附件的内容哈希，并补回缺失文件。已有路径内容不同则停止，不覆盖已有文件。数据库历史恢复仅恢复结构化内容；附件若已缺失，优先使用 Drive 完整备份。
4. 恢复状态先落到本机，自动上传暂停且刷新后仍保持暂停。核对正文、顺序、工作记录、图片和文件后，在同步窗口选择“替换云端”。
5. 数据库在同一事务中锁定预期版本、保存旧云端状态并写入新状态。云端在确认期间有变化会拒绝覆盖，请重新核对。

手工复制 JSON、只确认列表条数、只看到 Google 已连接，都不等于一次完整恢复演练。

## 验证入口

- `npm run test:static`：原有回归 + 导入/保护/保留/令牌加密/完整模拟备份及恢复/损坏文件/失败重试。
- `npm run test:browser`：原有页面回归 + 导入刷新、空云端覆盖拦截、未配置状态和独立恢复。
- GitHub Actions `Backup Database Isolation`：独立 PostgreSQL 中验证迁移、写入拦截、版本冲突、只读历史和跨账号权限。
- GitHub Actions `Worker Build`：打包 Worker 和静态资产，检查配置与模块兼容性。

本轮还没有确认此前数据丢失的根因。这些保护降低后续同类数据覆盖的风险；它们不会把已经丢失的历史自动补回来。
